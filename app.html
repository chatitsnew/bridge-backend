Module 3 — Bias audit, continued: an identity-blind check

Fairness check

Same resume text, different identity. The fields below are display-only — the scoring engine only ever reads the text in the candidate box above, so it never sees a name, a college's reputation, or a pronoun.

How this demo works — skill extraction and job scoring run on a deterministic rule engine (a ~30-node skills dictionary with weighted adjacency), not a live model call, so results are exactly reproducible in front of judges. The production version of Bridge replaces this layer with an LLM-driven skills inference agent (voice narratives, GitHub code analysis, synthetic skill validation) sitting behind the same three-module contract shown here — Discovery, Matching, Audit — so the interface and the bias-audit logic don't have to change when the inference engine does.
